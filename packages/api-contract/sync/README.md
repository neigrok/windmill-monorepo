# Sync conformance contract

The conformance contract of the sync engine ([engine.md](../../../docs/foundation/engine.md) §11). Every
implementation of the engine — the C++ server, and the JS, Swift and Kotlin clients — passes the golden
corpus for its role.

| Path | What it is |
|---|---|
| `registry.schema.json` | The registry format of §2.4, as JSON Schema. Code generation reads registries in this format. |
| `probe.registry.json` | `probe`: a test-only product, never shipped, whose eight types and three commands exercise every engine mechanism. The corpus is written against it. |
| `reference/` | The reference model: the engine's deterministic core in plain Node.js (ES modules, no dependencies). |
| `corpus/` | The golden vectors, generated by `reference/generate.mjs`. [corpus/README.md](corpus/README.md) documents every file's shape and the probe product's rules. |

## Commands

Run from this directory.

```sh
node reference/generate.mjs           # regenerate corpus/
node reference/generate.mjs --check   # exit 1 when corpus/ differs from what the reference generates
node --test reference/test/           # unit, property, replay-fuzz and regeneration tests
FUZZ_N=500 FUZZ_SEED=1 FUZZ_STEPS=300 node --test reference/test/fuzz/
```

## Registry format beyond §2.4

`registry.schema.json` carries what code generation needs and §2.4's sketch leaves out:

- a root with `registry`, `version` (the `Sync-Schema` header, `hello.schema`), `minVersion`
  (`hello.minSchema`) and `products`;
- per product, its `surfaces` (§7.9) and its device-scope rows (`device`, with `keyPattern` and
  `localOnly`);
- `key` for keyed types: a `ref` to another type, or a `tuple` of named refs whose JCS is the identity;
- `singletonId`, `derive.fallback` (D-26) and `seeded` (`seedMax`, `ordinalMax`, D-8);
- field `min` beside `max`, and `domain` as a structured value shape (string, number, boolean,
  fracKey, stamp, id, json, array, object; each `nullable`) where §2.4 has a string;
- command arguments as `{type, optional?, domain?}` and a command's `predicts`.
