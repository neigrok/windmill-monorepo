“Non-native” here means app-owned appearance or interaction. It does not mean web-based, inaccessible or defective. Source-confirmed implementation details are separated from behavior that still needs device validation.

Where the app departs from standard controls

01Gym · CoachAddress firstCustom control

Photo viewer owns zoom, pan and dismissal

The cover scales and offsets an image with custom gestures. Pan offsets accumulate without image-bound clamping; a zoomed image can be moved out of view. Swipe-down closes only at base zoom. There is no visible Close button, although accessibility Escape and Close actions exist.

Next step. Bound pan to the image viewport and add a visible Close control at every zoom level. Consider a zooming UIScrollView or Quick Look if their behavior fits.

Custom photo presentation can remain; gesture recovery and a discoverable exit need validation.

SOURCE · Gym/Coach/CoachTab.swift · 469–496
02JournalValidateCustom control

Mood and energy are hand-drawn sliders

Capsules, circles and eleven ticks replace Slider; a zero-distance drag calculates the value. These are native-rendered SwiftUI shapes, but not system slider controls. The code already supplies a 44 pt track target, adjustable accessibility actions and a clear action.

Next step. Compare with Slider(step: 1). If the bespoke track remains, test scroll arbitration, VoiceOver adjustment, contrast and both endpoints.

Intentional journal visual language; customization alone is not a defect.

SOURCE · Design.swift · 25–80
03JournalAddress firstBehavior

Tapping the number clears the answer

The displayed scale value is a plain button that sets the answer to nil. Its accessibility label explains Clear, but the visible number does not communicate deletion.

Next step. Make clearing visibly discoverable, or offer an explicit Clear action without changing the value label’s meaning.

Explicitly prescribed by journal/scales.md:38. Any revision needs a canon update.

SOURCE · Design.swift · 74–76
04JournalAddress firstBehavior

First focus moves the caret to the end

While unfocused, the editable text view does not receive the tap. A parent gesture requests focus, and the UIKit bridge selects the end of the text. A first tap on an earlier sentence therefore requests append behavior instead of placing the insertion point there.

Next step. Keep append-to-end for the explicit Write action; allow a direct tap on text to position the caret. Check selection and scrolling with long entries.

The editor itself is UITextView; this concern is the app’s focus policy.

SOURCE · JournalScreen.swift · 323–350; JournalScreen.swift · 465–478
05AccountValidateNative control customized

Sign-in fields have bespoke chrome

Email, code and link fields are real TextFields with 18 pt padding and rounded fills, with accent outlines on email and code. The code field retains one-time-code semantics; email retains an email keyboard and username content type.

Next step. Validate focus, error and disabled appearance, Dynamic Type, contrast and AutoFill. Prefer system field treatment where custom decoration adds no useful state.

This is custom appearance, not a replacement text-input engine.

SOURCE · AccountSheet.swift · 321–332; AccountSheet.swift · 349–351
06AccountAddress firstBehavior

Authentication uses state-swapped Back steps

The sign-in body switches on model.sheet. A toolbar Back button calls goBack to mutate that state; these steps are not pushed onto a navigation path. A surrounding NavigationStack does not itself provide interactive pop for those transitions.

Next step. Use explicit navigation destinations for drill-in steps, or verify and document the intended modal step flow. Test back gestures, keyboard focus and interrupted authentication.

A custom state flow can be valid; native navigation behavior must not be assumed.

SOURCE · AccountSheet.swift · 96–111; AccountSheet.swift · 160–177
07Gym · WorkoutValidateCustom control

Weight and reps use an app-owned keypad

A three-column button grid edits a string displayed as Text. This is not a system number-pad TextField; standard paste, selection and hardware-keyboard entry are not supplied by this component.

Next step. Keep the fast gym interaction if useful, but test Switch Control and VoiceOver order. Provide native text entry where paste or hardware keyboards are needed.

Intentional exception: ios-redesign.md:998–1003 specifies the keypad.

SOURCE · Gym/Components/SetEditor.swift · 51–98
08Gym · WorkoutValidateCustom control

Weight ladder replaces a standard stepper

Four custom buttons and their own rounded fills form the rack’s weight control. Reps use a custom minus/value/plus row (WorkoutScreen.swift:311–324). The repeated actions and presentation are app-defined rather than a system Stepper.

Next step. Verify each increment is clearly announced and large text retains the whole rack. Resolve the canon’s general native-button rule against the specific raised-rack treatment.

ios-redesign.md:879–881 prescribes ladder keys; the general glass/bordered rule is at line 341.

SOURCE · Gym/Components/SetEditor.swift · 125–150; Gym/Workout/WorkoutScreen.swift · 304–330
09Gym · LogValidateCustom control

Chart selection is manually implemented

Canvas and Paths draw the plot, with custom tap and long-press/drag selection. Accessibility point elements and earlier/later actions are already supplied.

Next step. Test point selection, scrolling conflicts and complete nonvisual data access. Swift Charts is an optional simplification, not a prerequisite for native quality.

Custom data visualization is legitimate content; its interaction costs still belong to the app.

10Gym · CoachIntentionalNative control customized

Coach composes its own message bar

The bar combines native PhotosPicker and TextField with a custom send seat: a 36 pt visual inside a 44 pt target. It is a bespoke composition rather than a stock chat composer.

Next step. Retain the composition; verify keyboard avoidance, multiline growth, disabled send and accessible labels.

Explicit design at ios-redesign.md:553–559. There is no single stock iOS chat composer to substitute.

11SharedIntentionalCustom control

Transient messages use a bespoke banner

RoomTransient defines layout, action, swipe dismissal and transition. This is app-owned transient behavior, even though its surface uses real system glass on iOS 26 and material on iOS 18.

Next step. Check announcements, persistent recovery actions and large-text overflow. Keep critical errors available long enough to act on them.

The shared band is intentional canon. Do not classify the genuine glass material as a fake native effect.

Native foundations worth preserving

Gym uses real TabView and NavigationStack (GymRoom.swift:30–44). Workout paging uses UIPageControl (WorkoutScreen.swift:209–227); chart range selection uses UISegmentedControl (LogDatedChart.swift:200–218). Journal editing is backed by UITextView (JournalScreen.swift:465–478).

Production Apple authentication uses the real Apple control (AccountSheet.swift:289–310). Primary and secondary actions use glassProminent / glass on iOS 26, with bordered fallbacks (Theme/RoomControls.swift:3–22). Circular seats and floating bands also use genuine Liquid Glass.

Other intentional custom content includes the journal gradient canvas (Design.swift:4–13), handwritten guidance (InkNotes.swift:15–98), brand typography (Theme/TypeScale.swift:15–28), welcome cards (WindmillApp.swift:224–247) and onboarding artwork. Onboarding’s paging remains native (Onboarding.swift:106, 189–203). These are inventory observations, not defect reports.

Device verification checklist

These checks are proposed, not executed as part of this source review.

  • iOS 18 and iOS 26: light/dark appearance, increased contrast, Reduce Transparency and Reduce Motion.
  • VoiceOver, Switch Control and accessibility text sizes: slider actions, keypad order, chart data, banner actions and visible exits.
  • Photo cover: extreme pan/zoom, reset, dismissal at every scale and rotation.
  • Journal: first tap mid-sentence, selection, long-entry scrolling, explicit append, and clear-value discoverability.
  • Authentication: AutoFill, pasted code/link, hardware keyboard, back gesture, keyboard transitions and interrupted requests.
  • Gym: keypad input, repeated ladder taps, plot gestures versus scrolling, composer growth and keyboard avoidance.

Scope & reference standard

This report reviews source in the current working tree at apps/ios/App. It is not a runtime validation, screenshot comparison or TestFlight audit. No app behavior was changed. Source links are relative to this report; printed line ranges remain useful where a browser does not interpret source anchors.

The written canon is iOS redesign and journal scales. Intentional exceptions are called out so design decisions are not mislabeled as bugs.

Apple’s slider guidance, text-field guidance, accessibility guidance and UISlider reference are comparison standards, not evidence that a particular custom element is defective.
