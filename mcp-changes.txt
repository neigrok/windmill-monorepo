Windmill MCP — friction ledger.

Open ergonomic defects on the MCP surface. One line each: the friction, then what would fix
it. Log new friction here as you hit it; delete an entry when it ships.

- [icon] A node's icon can be set at birth (create_node, import_subgraph) and by no edit tool,
  while get_diagnostics reports empty-icon as a smell — a defect the tool surface gives the
  caller no verb to clear. Fold `icon` into annotate_node, or stop reporting empty-icon.

- [annotate_node] `description` caps at 4000 and always replaces, so a node used as a running
  work log has to be rewritten and shrunk each time. Add an append mode, or raise the cap.

- [set_progress] `prerequisitesMet: false` reads the same for a real dependency violation and
  for a deliberate out-of-order completion. Add a per-node acknowledgement that the inversion
  is intended.

- [caps] Every length cap counts BYTES while its message and its published `maxLength` say
  characters; they diverge on non-ASCII. Both halves live in
  backend/products/roadmap/domain/Command.h.

- [tending] The unknown-argument refusal lives on the MCP wire, in
  CompositeToolHost::callTool. A tend runs ScopedToolHost → RoadmapTools directly, so a tending
  agent's misnamed argument is still dropped in silence.

## 2026-08-25 · annotate_node / create_node — the 4000-char description cap is a blind retry loop

Writing a wave node's description (the Live Activity ruling, with its verified API facts and the
latent bug it uncovered) took FOUR round trips: 5181 → 4058 → 4279 → 4150 → fit. Each refusal says
"description is N characters, max 4000" — which is the length I sent, not the length I may send in
the part that matters, and not which field overflowed when several are long.

Two cheap fixes, either would have made this one trip:
1. **Say the overage, not just the size** — "1181 over" is directly actionable where "5181, max 4000"
   makes me estimate and undershoot, which is what happened twice.
2. **Accept and truncate at a word boundary, returning `truncated: true` and the kept length**, the
   way `summary` already truncates a description for reads. A node annotation is prose; losing the
   tail is almost always better than losing the write, and the caller can decide whether to re-send.

Worth noting the cap itself is the real problem for this use: a node that records a ruling, its
evidence at file:line, and what it supersedes does not fit in 4000 characters, and the alternative —
splitting one decision across two nodes — makes the tree worse. `create_node` shares the limit, so a
node cannot even be born with its reasoning attached.

## 2026-09-03 · import_subgraph — a colliding kind sent without label/description is blanked

Seen on the live stack: re-sending `kinds: [{id: "build", hue: "terracotta"}]` for a kind that
already exists set its label and description to "". That is the documented upsert ("scalar fields
are replaced"), but a client that copies `get_tree` with the DEFAULT `kindFields` (which omits
`description`) and sends it back erases every kind description in silence. Fix: an omitted kind
field on a collision leaves the existing value (the way annotate_node treats an omitted field), or
the receipt names the kinds whose fields were blanked.
