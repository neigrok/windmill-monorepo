The local Coach archive holds the exact serialized onboarding body, request identity and originating owner/chat/replica before POST. Recovery reads that identity; a retry uses the retained body. Pending work belongs to the application scope and its originating chat, independent of selection.

Each import result has its own engine device-value key. The engine's Add operation merges device values by key, so separate keys retain unrelated receipts without extending merge behavior. Product records and their receipt share one Plan and storage transaction; fingerprint comparison makes replay independent of a chat's saved-state cache. The shared movement-creation helper retains Other equipment and signed load metadata in routine saves and onboarding batches.

The onboarding route remains the bounded installation-authenticated routine-document API. Android's account Coach continues using its current server executor. Visible signed-out states and postponed action cards have no source changes in this task.
