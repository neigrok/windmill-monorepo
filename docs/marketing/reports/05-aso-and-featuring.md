# 05 · Prepare a listing for the product the visitor can install

**Deferred until a public store release has an owner and a candidate build.** A lifter finding the beta
today gets the verified native route in [report 01](01-store-readiness.md). The founder can reuse the
pilot's descriptions of the job when preparing store material.

| Asset | First draft | Acceptance check |
|---|---|---|
| Default listing | Lead with a repeatable workout. Show routine, set entry and history in that order, using a sample program. | Every claim and screenshot matches the release candidate on that platform. |
| Product coverage | iOS carries Gym and Journal. Android carries Gym. Roadmap is a web destination. | Follow each CTA from the intended region on a supported device. |
| Custom product page, if warranted | Start with one audience whose intent differs from the default, such as iOS journal writers. Match the creative to what that build offers. | Use the approved page's unique URL and verify arrival. Record page-level counts where available. |
| Editorial nomination, if warranted | Tell one concrete story about what is distinctive in the native release. Submit it with a real launch or update. | Save the submission status. Forecast no placements or installs from a nomination. |

Apple reviews custom-page assets and lets developers nominate an app for editorial consideration. A product
page URL identifies the page. Establish any downstream attribution separately.
[Apple custom product pages](https://developer.apple.com/app-store/custom-product-pages/) ·
[Featuring nominations](https://developer.apple.com/help/app-store-connect/manage-featuring-nominations/nominate-your-app-for-featuring)

**First read after release.** Record product-page views, first-time downloads and their reporting window by
platform and source where available. Check whether referred users activate. Sparse counts support checking a
misleading headline or broken route. Only schedule a split test when the expected traffic can distinguish a
worthwhile improvement. New prompts and in-app surfaces need an approved design and an available experiment
slot.
