# 07 · Use the existing share path before commissioning new cards

**Roadmap pilot support.** The founder publishes the original starter from an account that owns it, opens
the link signed out, forks it into a test account, completes a step and checks the new tree's owner. Verify
that subsequent edits affect the copy. The participant can keep that copy private. Use the working link for
[report 11](11-roadmap-seed-trees.md). [Roadmap sharing contract](../../PRODUCT_LOG.md#roadmap)

Where coverage permits, count visitors to the starter, actual forks, activated participants and mature
returns separately. A link copy or image export can happen without a recipient opening it. The fork's
provenance shows its source tree but does not identify who referred the visitor. Record unassigned traffic
separately. [Funnel views](../../../backend/db/FUNNEL.md)

**Gym pilot support.** The native apps already describe finished-session sharing. Check the behavior on the
actual pilot build before showing it. Use only the founder's sample workout in demonstrations. Anyone can
participate in the Gym test while keeping every session private. [iOS Gym](../../../apps/ios/App/README.md)
· [Android Gym](../../../apps/android/README.md)

**Later card experiment.** If returning users choose to share and recipients struggle to understand or open
the link, inspect the break before adding a card. A proposed card needs a user-controlled preview, an
explicit share action, a destination usable by that recipient and an approved design. In one free slot,
compare completed referrals that lead to activation with the existing link experience. Stop if the link
fails, reveals unexpected information or users report pressure to publish. Keep Journal outside the sharing
campaign.
