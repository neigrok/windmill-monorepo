# 16 · Does one relevant invitation help an established user?

**Deferred lifecycle experiment.** Start after one product has demonstrated sustained use, a second
destination has an independently verified activation definition, a slot is free and the owner has approved
the proposed surface. A four-week Gym user might want a Roadmap tree to plan a training block. Roadmap opens
on the web. The invitation must identify that destination clearly. [Surface map](../../../STRUCTURE.md)

**Design the comparison.** Define eligibility, baseline first-product return, second-product activation,
observation windows, the smallest benefit worth shipping and the maximum acceptable drop in first-product
return before recruitment. Use the observed baseline to size the test. Exclude people who already use the
destination. Randomly assign eligible accounts once to a single quiet invitation or a no-invitation group.
Keep invites out of workouts and writing sessions. A dismissal ends the invitation.

**Readout**

| Measure | Denominator and source |
|---|---|
| Second-product activation | All accounts assigned in each group. A Roadmap activation requires an owned tree with at least three present nodes and a first completion within 48 hours of creation. |
| Primary-product retention | Accounts with a mature return window in each assigned group. Record the baseline and both observed rates. |
| Invitation use | Aggregate views, dismissals and destination opens only if those events exist and have been verified. Product data and personal content stay out of the event payload. |

Count observed second-product activation in the holdout too, since some users will find the product
themselves. Retain the invitation only if the incremental gain clears the predeclared threshold without a
material primary-product loss. If the sample is too small to resolve either quantity, leave rollout
deferred. Do not infer subscription value from a second-product visit.
