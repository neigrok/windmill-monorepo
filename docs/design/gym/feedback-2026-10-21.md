# Gym and Coach interaction contract

Current requirements from the 2026-10-21 owner feedback. These requirements govern the affected
iOS screens and shared Coach behavior. They are acceptance criteria, not verification results.
Existing gym colors, type roles and native navigation remain the foundation.

## Exercise identity and load

Editing an exercise presents its name and an Equipment picker in one native form. Saving changes
the existing exercise identity. Routine rows, logged sets, workout detail, movement records,
search and Coach resolve the current name from that identity. Preserve set amounts, timestamps,
kind and exercise references; renaming never forks a movement or rewrites performed facts.

Equipment is a labeled icon picker, not an unexplained glyph. Lead with Barbell, Dumbbells and
Bodyweight; retain Machine, Cable and Kettlebell. Existing values must not be coerced. Use the
same symbol and label in the exercise editor and Coach's review. The picker
uses native menu/list selection and a visible checkmark; its accessible label includes the value.
Bodyweight is the name for the owner's “none” category and still supports added weight.

| Equipment | Entered weight | Volume convention |
| --- | --- | --- |
| Barbell | Entire bar and plates | Entered load × reps |
| Dumbbells | `kg each`; **Dumbbells lifted** selects One or Two | Entered load × declared count × reps |
| Bodyweight | Added load; zero for unweighted, negative for assistance | Positive added load × reps; no invented body mass |
| Machine, Cable, Kettlebell | Existing declared load convention | Preserve existing behavior |

The logger, set editor, target editor and review expose the same load basis. Dumbbell readouts use
**16 kg each**; barbell readouts use **32 kg total**. Eight reps with two 16 kg dumbbells or a
32 kg barbell produce 256 kg of external-load volume. Volume remains a load/repetition measure,
not a claim of equal effort. Preserve which set kinds
the existing aggregate includes. Do not double the displayed per-dumbbell number or an exercise's
per-dumbbell strength estimate.

Equipment correction must not rewrite raw logged weights. Historical volume resolves the exercise
identity and its current equipment/count; the editor states that the change updates historical
volume. One-dumbbell movements use an explicit count of One, paired movements Two. Never infer
quantity from an exercise name.

## Routine and workout controls

- Routine exercise rows are immediately reorderable through native drag handles. Remove the
  Reorder/Done mode toggle. Tapping a row still edits it; dragging the handle reorders it. Expose
  accessible move actions, preserve stable row identity and keep order in the draft until Save.
- Removing an exercise uses a native red `trash` action with the destructive role and a meaningful
  accessible name. Remove the old text-only Discard treatment. Retain the existing operation's
  confirmation policy; a row removal does not delete that exercise's training history.
- Weight keys and reps minus/plus each own their full visible target, at least 44 × 44 pt, with
  48–56 pt preferred in the rack. The centered numeric editor does not overlap their hit areas.
  Parent paging gestures must not consume the initial touch or an ordinary tap.
- Touch-down visibly changes the pressed control immediately through its native press treatment;
  a subtle scale to 0.96 is acceptable when the native treatment needs reinforcement. Accepted
  taps update the local draft immediately. Use monospaced digits and `numericText` for the changed
  value, without moving surrounding controls. Network work never gates press feedback.
- Release/cancel returns the control to rest. Invalid decrements are disabled, without fake success
  animation. Rapid taps each apply once. Reduce Motion keeps immediate state and color feedback
  without scale or numeral travel. Preserve the canon's absence of log-set sound/haptic.

The workout remains one clear hierarchy: movement identity and quiet clocks above a compact
ledger, with a grounded rack and one primary Log set action. Avoid extra cards, captions, repeated
titles and competing accent actions. Keep native navigation, sheets and system destructive red.
Spacing around content may tighten; text and touch targets may not.

## Live Activity

The Lock Screen and expanded Island top-right clock is **since last set**. Its anchor is the latest
non-deleted valid set across the whole active session, including locally accepted unsynced sets.
Before the first set its anchor is session start and its accessible name is **Workout time**.
Workout elapsed, if shown, is secondary and has a distinct accessible name.

Use system timestamp-driven timers and monospaced digits. Logging resets the since-set anchor
once after the local write succeeds; acknowledgment does not reset it again. Moving exercises,
changing rack values, backgrounding and reconnecting do not reset it. Deleting the latest set
selects the preceding timestamp or session start. Preserve existing stale/locked-action rules.

## Empty roots

Empty Routines has the native empty-state identity and one bottom-trailing `plus` control,
accessible as **New routine**. Remove the central Set up routines action and duplicate top-right
creation control. The creation destination is the routine builder; Coach remains its own tab.

The Log's weight-entry affordance follows the same rule: a bottom-trailing `plus`, accessible as
**Weigh in**, opening the native entry sheet. Bodyweight remains a reading/correction destination.
Remove duplicate top-right weight creation controls. A seat is at least 44 pt, clears the
tab bar/accessory and safe area, and never obscures the last row.

## Coach's first conversation

Coach opens with one locally rendered conversational greeting, in the same typography as an answer:

> I’m Coach. I can help you plan training and understand your log. Tell me what you’re working on,
> or share a routine.

It makes no claim to have read the user's records. Render two compact actions beneath the greeting:
**Add screenshot** opens the native photo picker; **Build myself** opens the routine builder.
Keep the greeting and actions together in scrollable content, with enough bottom inset to expose
both actions above the composer at accessibility text sizes. The composer remains **Ask about your
training**. There is no goal form, goal shortcut, mandatory
days/equipment selector, Just log action or remaining-allowance indicator. Goals and constraints
can arise through plain dialogue. Coach can ask one useful question naturally when context is
missing, and can participate in ordinary conversation without a narrow-topic refusal.

The greeting and onboarding actions persist until the first user message is successfully accepted
by the send boundary. Opening/closing a photo picker, editing, changing tabs, restarting, a refused
send and a failed send do not consume onboarding. An accepted attachment-only message counts.
The greeting is not a billable model turn or a saved user message. Preserve draft and attachment
on failure. Build myself may change destination but does not pretend a message was sent.

## Routine confirmation and connection truth

Every routine Coach creates is first a pending draft. No routine lands merely because generation
completed. Show its real name, movement count and **Review**. The native review shows all movements,
equipment and targets, with **Save routine** pinned at the bottom. Multiple routines identify each
routine and use **Save routines** when the confirmation commits the collection atomically. Closing
review preserves the draft. Show **Routine created** and **Open routine** only after the user's
explicit save succeeds. Retry and resume use stable identities and cannot create duplicates.
Existing-routine edits retain their human Apply path. External MCP authorization is separate.

Generation status and transport status are separate. A quiet interval between deltas is still
generating, not evidence that the user's connection failed. Show **Reconnecting…** only after a
real transport failure; resume the same logical turn and clear it when transport recovers. Preserve
partial text and completed receipts. A terminal failed turn says **Response interrupted.** with
**Retry**; a completed turn has no stale warning. A partial turn must never look silently complete.
Stop preserves existing output and does not claim a completed save was undone.

## Exhausted access

Only present access recovery when a send is refused. Signed out: **Sign in to continue.** with
**Sign in**, preserving the conversation, draft and attachment through authentication. Do not
show a remaining count or imply a new chat resets access.

Signed in without Windmill One, show **Windmill One** as an informational destination when useful.
Checkout is closed, so the destination must state **Subscriptions aren’t available yet.** and must
not contain an enabled Upgrade/Buy control or promise that payment will immediately restore Coach.
When actual checkout becomes available, **Upgrade** can replace the informational route. Use a
server-supplied reset fact only when one exists. An existing One member gets the actual limit and
recovery, never an upsell to a plan they already have.

effects separately; screenshots do not verify hit testing, persistence or network behavior.

## Release compatibility

Routine confirmation requires clients that render `routineDrafts` and call explicit confirmation.
Older clients cannot save these pending drafts. Coordinate backend and client release availability,
or provide an explicit update-required route before returning an unusable draft to an older client.
A client that cannot review must never silently create the routine as a compatibility fallback.
Deterministic provider fixtures can verify the draft/save protocol; they do not establish actual
model conversational behavior.
