# THIS FILE IS NOT THE WHOLE ANSWER A CRAWLER GETS. Cloudflare's managed robots.txt is
# switched on for this zone and PREPENDS its own block to whatever is served here —
# measured 2026-08-12: `Content-Signal: search=yes,ai-train=no,use=reference` for everyone,
# then `Disallow: /` for ClaudeBot, GPTBot, Google-Extended, CCBot, Bytespider, Amazonbot,
# Applebot-Extended, meta-externalagent and CloudflareBrowserRenderingCrawler. So the AI
# crawlers are blocked by a dashboard setting, not by anything in this repo, and the rules
# below only ever add to that. Fetch the live URL before concluding what we allow — and
# change the AI half in the Cloudflare dashboard (AI Crawl Control), not here.
# Windmill is a single-page app plus static pages: the product landings
# (/roadmap, /journal and /gym — each a static shell that boots the SPA) and the shelf
# (connect, privacy, terms, changelog). connect.html is the crawlable MCP
# works-with page; the interactive workbench lives at the #/connect hash
# route. Hash routes (#/app, #/t/:id, #/connect, #/showcase, #/welcome) are
# URL fragments, never sent to the server, so there is nothing per-route to
# allow or block. The old /products/<name> URLs 301 to /<name>.
#
# /gallery and /t/:id are server-rendered, not static files: the gallery lists
# every tree its owner chose to list (as real anchors, which is how a crawler
# reaches the trees at all), and each /t/:id share page carries that tree's own
# meta. A tree that was never listed is `noindex` on its own page and appears
# on no wall — being crawlable is the owner's choice, made in the share dialog.

User-agent: *
Allow: /

# Do NOT disallow /assets/ — crawlers must fetch the JS/CSS bundles to
# render the client-side landing page. Blocking them would hide all content.
